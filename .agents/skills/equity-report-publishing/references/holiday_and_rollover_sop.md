## 一、美股冬令时 vs 夏令时精准北京时间对照与全时段主刊节拍

> **切换规则**：美东**冬令时（EST = UTC-5，北京 `+13h`）**自 11 月第一个周日至次年 3 月第二个周日；**夏令时（EDT = UTC-4，北京 `+12h`）**自 3 月第二个周日至 11 月第一个周日。  
> **一体化三班次顺序执行与单向截点宽限**：每日 **`07:30` 早报 / `11:30` 午报 / `18:00` 晚报**（北京时间）先验证当期黄金，再由权益读取相同 `edition_id` 的快照。黄金截点须早于或同分钟于权益，差值最多 **6 小时**，两轨截点与日报 `chart_live.as_of_full` 各须落在所标班次 **`[-5 分钟, +6 小时]`** 单向窗口内（早班 `07:25–13:30` / 午班 `11:25–17:30` / 晚班 `17:55–次日 00:00` CST）。假日、周末或美东非发布窗（含 `07:30` 与 `11:30`）无盘中观测时，双轨 `brent_live_usd` 与 `vix_live` 允许同口径同时留空。

### 三市休市三模式速判与 `gold_event_id` 跨轨校验规则

班次开始运行 `python3 equity/lint_equity.py --plan <edition_id>` 获取三市出刊或复用计划（可在刷新快照前运行）。以最新官方交易日历维护 `state/market_state.json` 的 `calendar_overrides`，例外结构与验收要求见[权益日报规格](../../../../equity/DAILY_REPORT_SPEC.md)：

- **模式 1（三市均正常开市）**：执行全时段完整主刊标准（周一至周五 `07:30` / `11:30` / `18:00` 三市均发 `main` 主刊，必含 ≥2 张矢量图）。
- **模式 2（局部休市或半日市）**：正常开市市场发 `main` 主刊；休市/半日市市场使用 `resources/daily_light_or_holiday_template.md` 出版升级版 `holiday_watch` 守望刊（建议 ≥1 张矢量图；沿用 `YYYY-MM-DD_{0730,1130,1800}_{market}.md`）。
- **模式 3（三市齐休）**：无 P0/P1 突发重磅时不发冗余新日报，三市沿用旧稿，仅更新 `daily/INDEX.md` 与 `daily/CHANGELOG.md` 顶部休市守望行（周日 `18:00` 班同步刷新 `SCORECARD.md` 与三大深研库周度校准）。
- **`gold_event_id` 跨轨强校验（`edition_plan.py` 实装）**：
  1. 当权益 `calendar_overrides` 条目填写 `gold_event_id`（如 `us_thanksgiving_2026`、`global_new_year_2027`、`us_good_friday_2027`）时，引擎自动交叉核对 `gold/market_calendar.json` 中同名 `id` 事件；
  2. 强制要求：① 起止日期 `date_cst` / `end_date_cst` 与黄金 `date` / `end_date` 完全一致；② `markets_affected` 中所有市场均映射到黄金 `markets`（`a_share -> CN_A_SHARE`、`hk_stock -> HK_EQUITY`、`us_stock -> US_EQUITY`）；③ 单市美股声明 `affected_sessions` 时必须与黄金 `affected_editions` 完全一致；
  3. 同一条带 `affected_sessions` 的规则严禁混写美股与 A 股/港股；单日美股休市窗口（`mode_2_watch_brief`）兼容经典 2 场集合 `{当日 1800, 次日 0730}` 与次日为工作日时的 3 场集合 `{当日 1800, 次日 0730, 次日 1130}`；不同市场实际休市日期不同时须拆条登记；如 `2027-01-01`（`global_new_year_2027`）因美股早/午刊均按前一日美东交易日（`2026-12-31`）判定，`edition_plan.py` 会自动判定 `2027-01-01_0730` 与 `2027-01-01_1130` 美股发 `main`、A/港复用，而 `2027-01-01_1800` 与 `2027-01-02_0730` 三市复用。

> **根目录冻结与零未授权 Shell 铁律**：工作区根目录 `<REPO_ROOT>/equity` **永久不改名**；沙箱内严禁调用 `mv`/`rm`，物理清理旧档一律登记清单交由用户确认执行；归档不得让曾公开的静态网页地址失效。

1. **第 1 步｜月初零超时原子滚存三旗舰与 `report_meta_*.json`（同步黄金月度归档）**：
   - **严禁手写 636 KB 全量旗舰触发 300s 超时！** 当 `lint_equity.py --plan` 提示跨月切换 `period_slug`（如 `2026_11` → `2026_12`）时，用 `write_file` 写紧凑 `equity/state/_rollover_patch.json` 并运行预授权 **`python3 <REPO_ROOT>/scripts/patch_state_dbs.py --rollover-equity-month`**（原子克隆 `a_share_market_report_2026_12.md`、`hk_stock_market_report_2026_12.md`、`us_stock_market_report_2026_12.md` 与各自 `_latest.md` 保持字节 100% 一致，并同步更新 `report_meta_a_share.json`、`report_meta_hk_stock.json` 与 `report_meta_us_stock.json` 中的 `"period_slug": "2026_12"`、`"version": "2026年12月刊"`、`"page_footer"`、精确浮点 `"as_of_year_float"`、`kpis` 及与附表二/`deep_dossiers.json` 100% 对齐的 `stock_pool_count`）。
   - 若同日同步归档上月黄金历史双账本（`gold/daily/{CHANGELOG,AUDIT_LOG}.md`），写紧凑 `gold/daily/_archive_patch.json` 运行预授权 **`python3 <REPO_ROOT>/scripts/patch_state_dbs.py --archive-gold-ledgers`** 无损归档至 `gold/daily/archive/{CHANGELOG,AUDIT_LOG}_YYYY_MM.md`。
2. **第 2 步｜源稿严检、全市场 K 线抓取、静态门户构建严检与纯网页发布**：
   - 运行全量验收 `python3 <REPO_ROOT>/equity/lint_equity.py --strict`，确认三份旗舰源稿与 `*_latest.md` 字节一致、21 张矢量 SVG 图实时演练零重叠、三大扩展数据库完整同步且 Gate 0–5 / Gate 3B / 跨项目 Gate C1–C3 全部退出码 0、0 错 0 警；
   - 终检全绿后，先执行 `python3 <REPO_ROOT>/scripts/fetch_kline_data.py --scope all` 刷新全市场 480+ 标的静态 K 线分片至 `equity/state/klines/`，再推进本期令牌到 `publish` 阶段，通过 `python3 <REPO_ROOT>/scripts/publish_site.py --edition-token <token>` 构建静态门户、通过 S1–S7 严检并推送至 `origin/main`，再执行 `python3 <REPO_ROOT>/scripts/edition_run.py complete <token>` 验证对应 GitHub Pages 部署。无活动班次时按根仓规则使用人工入口。

5. **第 5 步｜留痕与归档移交清单**：写 3 键 `equity/state/_audit_patch.json` 经 `scripts/patch_state_dbs.py --prepend-equity-audit` 在 `state/audit_ledger.md` 倒序置顶登记新月刊核验记录；在 `daily/CHANGELOG.md` 仅以纯读者中文记录新月刊观点变化（零工程/RSI 词）。
